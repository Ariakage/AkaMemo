# ADR-0004: 连续 24 小时录音作为产品目标

- 状态：已接受
- 日期：2026-10-28
- 决策者：用户
- 验证状态：G-001 未通过（待执行）
- 关联：`Q-001`、`Q-002`、`Q-003`、ADR-0003、ADR-0005、`../specs/24h-feasibility.md`

## 背景

用户确认 `Q-001` 采用定义 A：AkaMemo 的产品目标是**连续 24 小时不间断录音**，不是“全天候可用/按需录音”，也不是“白天连续、夜间充电”。

当前已知约束：

- watchOS 录音必须在应用前台启动，后台只能延续已开始的音频会话；
- 来电、Siri 等中断后，后台自动恢复不可靠；
- `WKExtendedRuntimeSession` 最长约 1 小时，无法覆盖全天；
- Apple Watch 在连续麦克风采集 + 编码 + 分片落盘下的续航尚未实测；
- 热、存储、传输积压都可能影响 24 小时稳定性。

因此，“连续 24 小时”是产品要求，但工程可行性尚未证明。

## 选项

1. **A：连续 24 小时不间断录音（已选）**
   - 优点：产品承诺清晰，所有功耗、存储、传输设计都有硬约束。
   - 缺点：当前硬件很可能无法单次充电完成；需要长时间真机验证。
2. **B：全天候可用**
   - 优点：更现实，允许充电间隙续录。
   - 缺点：用户明确不选。
3. **C：白天佩戴期间连续**
   - 优点：折中。
   - 缺点：用户未选。
4. **外接电源/充电宝**
   - 优点：可能实现 24h。
   - 缺点：改变产品形态与佩戴体验，需要用户确认。
5. **Workout Session 保活**
   - 优点：可能延长后台运行。
   - 缺点：影响 Activity 圆环、用户体验误导、审核解释成本高。

## 决定

1. 产品目标定为 **A：连续 24 小时不间断录音**。
2. 在 **G-001 可行性门禁** 通过前：
   - 不得对外承诺 24h；
   - 不得把 24h 写入营销文案、App Store 描述或 TestFlight 说明；
   - MVP 验收以门禁结果为准。
3. 门禁按 `../specs/24h-feasibility.md` 执行，必须真机、完整 24 小时、可复现。
4. 门禁未通过时：
   - 记录实际最大连续时长与失败原因；
   - 评估降码率、降采样、减少落盘频率、外接电源、Workout Session 等缓解方案；
   - 任何降低产品目标的改动，必须新写 ADR 并由用户确认，不得静默改为 B/C。

## 后果

**正面**

- 产品目标清晰，录音、功耗、存储、传输设计都以 24h 为硬约束。
- 可行性门禁把“能不能做到”与“要不要做”分开，避免用营销倒逼工程。

**负面**

- 当前硬件很可能无法在单次充电下完成 24h 连续录音；门禁可能失败。
- 若失败，需要重新定义产品或引入外接电源/降级策略。
- 24h 测试成本高，需要多轮真机测试与设备占用。

**必须补做**

- 按 `../specs/24h-feasibility.md` 执行 G-001。
- 在 `../specs/recording.md` 记录实测数据。
- 门禁通过后，把本 ADR 的“验证状态”改为“G-001 已通过”，并更新成功指标与对外口径。

## 验证

- 门禁 G-001 的通过标准见 `../specs/24h-feasibility.md`。
- 验证必须覆盖至少 3 种设备/系统组合、2 种码率、iPhone 在旁/不在旁。
- 结果必须包含：连续时长、电量曲线、热状态、分片完整性、丢失/损坏数、存储占用。
- 若启用 GPS，还必须通过 ADR-0005 / G-002；G-001 通过不代表组合目标通过。

## 回退

如果 G-001 失败且无可行缓解：

1. 新写 ADR 提议改为 B/C 或引入外接电源；
2. 由用户确认；
3. 更新产品、需求、录音规格与营销口径；
4. 不得在未确认前继续按 24h 承诺开发。
