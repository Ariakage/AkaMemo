# ADR-0005: 录音期间记录 GPS 轨迹并支持 GPX

- 状态：已接受
- 日期：2026-10-28
- 决策者：用户
- 验证状态：G-002 未通过（待执行）
- 关联：`Q-019`、`Q-020`、`Q-021`、ADR-0004、`../specs/gps-tracking.md`

## 背景

用户要求记录 GPS 信息，并希望以 GPX 轨迹形式使用。位置能把录音放回真实场景（在哪、走了哪条路、停留多久），但会显著增加：

- **功耗**：连续定位是 Apple Watch 的主要耗电来源之一；24h 录音本身已接近硬件极限。
- **隐私**：轨迹可推断住址、工作地、作息与社交关系，比录音更敏感。
- **平台复杂度**：watchOS 没有可用的“始终允许”定位；后台定位需要特定配置，且不能在后台随意停止/重启。

同时，产品目标已是连续 24 小时录音（ADR-0004），GPS 会直接挤压续航预算。

## 选项

1. **录音期间记录 GPS，本地存储，按需导出 GPX（已选）**
   - 优点：满足需求；数据留在设备；导出格式通用。
   - 缺点：功耗与隐私成本高；后台定位可靠性需实测。
2. **只在 iPhone 端记录位置**
   - 优点：实现简单、省 Watch 电量。
   - 缺点：Watch 离开 iPhone 时无轨迹；不能代表佩戴者位置。
3. **只记录城市级/时区位置**
   - 优点：隐私风险低、功耗低。
   - 缺点：不满足用户对轨迹的需求。
4. **云端记录/实时上传**
   - 优点：可跨设备查看。
   - 缺点：隐私与成本；MVP 不需要。

## 决定

1. 录音会话期间记录位置轨迹，与 `RecordingSession` 关联。
2. 位置只在设备本地存储；默认不上传。
3. 使用 watchOS Core Location 的 **When In Use** 授权；**不请求 Always**（watchOS 上不可用且行为未定义）。
4. 使用 Location Updates 后台模式 + `allowsBackgroundLocationUpdates`，并在**前台启动**；若目标系统提供 `CLBackgroundActivitySession`，优先评估使用。
5. 轨迹以 JSONL 追加写入；导出时生成 GPX 1.1。
6. 用户可全局或按会话关闭定位；拒绝定位时录音仍可用，只是没有轨迹。
7. 删除录音时级联删除轨迹与 GPX 缓存。
8. **G-002 门禁通过前，不得对外承诺“24h 录音 + GPS”。**
9. **Q-019**：GPS 采用**高精度、低频率、每 5 分钟一个点**；低电量/热状态下降级为 `HundredMeters`，但保持 5 分钟频率。
10. **Q-021**：GPX 导出按选中会话/片段的**开始与结束时间裁剪**，不导出会话外轨迹。
9. 首次授权后，GPS **默认随录音开启**；设置中 **MUST** 提供全局关闭开关；**不每次询问**。关闭后新会话不再采集，已有轨迹保留直到用户删除。

## 后果

**正面**

- 记忆带位置上下文；GPX 可导入地图、运动或分析工具。
- 本地存储、按需导出，隐私边界清晰。
- 定位失败不阻塞录音，降级路径明确。
- 默认开启减少操作成本，轨迹更完整。

**负面**

- GPS 显著增加耗电，24h 组合目标更可能失败。
- 室内、隧道、城市峡谷会有轨迹缺口；5 分钟采样意味着点稀疏，移动中允许 ≤6 分钟缺口，不能承诺“全程有轨迹”。
- 位置权限、后台定位与导出增加审核与用户信任成本。
- 默认开启意味着用户可能忘记关闭；必须在设置与录音界面清晰展示状态。

**必须验证**

- G-002：24h 录音 + GPS 的续航、轨迹连续性（5min 采样）、精度、GPX 裁剪与有效性。
- 锁屏/退后台/中断后的定位行为。
- 低电量模式下的定位降频策略。

## 验证

见 `../specs/gps-tracking.md` 的 G-002。未通过时按 ADR-0004 的流程评估降频、iPhone 辅助定位、Workout Session 或调整产品目标；需用户确认。

## 回退

- 如果 G-002 失败：优先降低 GPS 采样频率/精度，或把 GPS 改为可选功能；仍失败则新写 ADR 调整 24h 组合目标。
- 如果后台定位不可用：改为“仅前台/会话内记录”并明确告知用户，不静默假装有轨迹。
