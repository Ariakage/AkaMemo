# ADR-0008: 实时诊断日志

- 状态：已接受
- 日期：2026-10-28
- 决策者：用户
- 验证状态：G-005 未通过（待执行）
- 关联：ADR-0007、`../specs/diagnostics.md`、`../privacy/privacy-and-security.md`

## 背景

用户需要实时日志，用于确认录音保活、中断、传输、转写与电量状态。约束：

- Apple 的 OSLog 适合系统日志，但没有公开的“应用内实时读取”API，不能直接做日志查看器。
- 录音、转写、位置数据高度敏感；日志绝不能成为泄露渠道。
- 录音链路要求日志不能阻塞音频回调或主线程。
- 需要可导出、可清空、可限流，且默认不上传。

## 选项

1. **只用 OSLog**
   - 优点：零额外基础设施。
   - 缺点：无法应用内实时查看；排查依赖 Xcode/Console。
2. **只用文件日志**
   - 优点：可持久化、可导出。
   - 缺点：实时性差；需要轮询；文件管理复杂。
3. **OSLog + 内存环形缓冲 + 可选 JSONL + AsyncStream UI（已选）**
   - 优点：实时、可控、可导出；隐私边界清晰。
   - 缺点：需要自建日志基础设施与脱敏测试。
4. **第三方日志 SDK**
   - 优点：功能多。
   - 缺点：依赖、体积、隐私与上传风险；MVP 不需要。

## 决定

1. `AppLogger` 双写 OSLog + 内存环形缓冲（默认 2000 条）+ 可选 JSONL 文件。
2. `DiagnosticsView` 在 iPhone 上通过 `AsyncStream` 实时展示，支持级别/分类过滤、暂停、清空、导出。
3. 分类固定：`recording`、`transfer`、`transcription`、`storage`、`location`、`battery`、`ui`、`diagnostics`。
4. 级别：`debug`、`info`、`warning`、`error`；Release 默认 `info`；`debug` 需用户显式开启。
5. 日志 **MUST NOT** 含音频、转写文本、经纬度、地址、文件名、用户内容；ID 截断；消息模板化。
6. 保留：内存 2000 条；文件 7 天/5MB；可清空；导出前提示隐私风险；**不上传**。
7. Watch 健康事件/心跳按低频批量转发到 iPhone 诊断视图；Watch 端紧凑视图为 P1。
8. 日志写入不得阻塞音频回调或主线程；使用 actor/异步队列。
9. G-005 门禁通过前，不得宣称“日志可用于远程诊断/自动上传”。

## 后果

**正面**

- 用户与开发可以在应用内实时看到录音健康、传输、转写状态。
- 出问题时能导出结构化日志，减少“无法复现”。
- 不引入第三方依赖；隐私边界可控。
- 与 ADR-0007 的看门狗/心跳天然配合。

**负面**

- 需要自建日志基础设施、环形缓冲、文件轮转与脱敏测试。
- 内存/文件配额需要管理；Watch 转发依赖连接。
- 调试日志若脱敏不严，仍有隐私风险。
- 实时 UI 可能影响性能，需要节流。

**必须验证**

- G-005：脱敏、配额、导出提示、Release 默认级别、实时性能、Watch 转发。
- 录音/传输高频日志下的 CPU/电量影响。

## 验证

见 `../specs/diagnostics.md` 的 G-005。未通过时：

- 优先降低日志量/刷新频率；
- 保留环形缓冲与 OSLog，关闭文件日志；
- 不得关闭脱敏或默认上传。

## 回退

- 如果实时日志影响录音性能：降低 UI 刷新频率、减少 debug 日志、改为手动刷新；不得阻塞音频回调。
- 如果文件日志引发隐私/存储问题：只保留内存环形缓冲 + 手动导出；默认关闭文件日志。
