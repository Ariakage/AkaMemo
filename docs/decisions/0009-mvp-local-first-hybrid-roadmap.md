# ADR-0009: MVP 本地优先、端上转写与后续混合/云端路线

- 状态：已接受
- 日期：2026-10-28
- 决策者：用户
- 关联：`Q-002`、`Q-003`、`Q-004`、`Q-016`、ADR-0010、ADR-0011、`../specs/transcription-and-search.md`

## 背景

用户给出的方向是：

- `Q-002`：混合（端上 + 云端）。
- `Q-003`：本地 + iCloud + 自建后端。
- 但明确限定：**MVP 阶段不上云**。

这需要把“MVP 交付范围”和“目标架构”分开，否则实现时容易把云路径提前引入，破坏 MVP 的隐私边界与进度。

同时：

- 音频参数定为立体声 96 kbps/声道 / 44.1 kHz（ADR-0011），24h 音频约 2.07 GB；iCloud/后端同步全部音频会带来显著存储、流量与配额压力。
- 用户使用个人 iCloud 账号与 `ariakage.com` 域名（ADR-0012）；iCloud/CloudKit 需要付费 Apple Developer Program。

## 选项

1. **MVP 端上 + 本地；混合/iCloud/后端作为后续路线（已选）**
   - 优点：MVP 隐私边界清晰、无后端运维、可离线；后续通过协议扩展。
   - 缺点：MVP 不能跨设备同步；后续需要迁移与云端合规评估。
2. MVP 直接上混合/云
   - 优点：一步到位。
   - 缺点：与“MVP 不上云”冲突；成本、审核、隐私、账号都提前变复杂。
3. 永久本地，不做云端
   - 优点：最简单。
   - 缺点：不符合用户的中长期目标。

## 决定

1. **MVP 范围**：
   - 转写仅在设备上完成（端上 provider）；
   - 数据仅存本地（iPhone 本地 + Watch 本地缓存）；
   - **不启用**云转写、自建后端、iCloud/CloudKit 同步、账号体系；
   - **不上传**音频或转写；不集成云端 STT API；不配置云端密钥。
2. **目标架构**（后续版本）：
   - 转写：混合（端上优先、云端可选，默认关闭）；
   - 存储：本地 + iCloud + 自建后端；
   - 账号：后端阶段再定（`Q-004` 延后）。
3. **接口先行**：
   - 业务层只依赖 `TranscriptionProvider` / `SyncProvider` 协议；
   - MVP 只注册端上 provider；云 provider 可以保留接口但不实现、不启用、不打包密钥。
4. **云路径准入**：
   - 任何云转写、iCloud 同步、后端上传，必须新写 ADR、单独用户同意、隐私评估与关闭开关；
   - 不得在 MVP 中以“实验/灰度”为名静默上传。
5. **数据模型为同步预留**：
   - 稳定 UUID、`updatedAt`、软删除/tombstone、相对路径；
   - 不把设备绝对路径、账号信息写入业务模型。
6. **iCloud/CloudKit**：
   - MVP 不启用；
   - 未来启用时，SwiftData + CloudKit 的 schema 约束（optional/default、无 unique constraint）需单独迁移（ADR-0010）。
7. **音频同步策略（未来）**：
   - 立体声 96 kbps/声道下 24h 约 2.07 GB；默认只同步元数据/转写，音频是否上 iCloud/后端由用户显式选择；
   - 不建议默认全量音频同步。
8. **Q-004**：MVP 不需要账号；账号体系延后到后端阶段。
9. **Q-014**：不做音频/转写导出；只做 Watch→iPhone 自动同步、校验手机文件后删除 Watch 文件。GPX 轨迹导出除外（Q-021）。
10. **Q-016**：需要备份；MVP 不上云，但允许 iOS 设备级 iCloud 备份包含音频/元数据；App 本身不上传。立体声 2.07 GB/天，用户需自行管理 iCloud 空间。
11. **Q-008**：允许蜂窝网络；MVP 的 Watch→iPhone 本地传输不受影响，未来云/同步可使用蜂窝（需用户设置）。
12. **Q-018**：iPhone 不需要后台播放/锁屏控制；不声明 iOS Audio 后台模式。

## 后果

**正面**

- MVP 无云端依赖，隐私与审核风险最低。
- 离线可用；无后端成本。
- 后续通过协议扩展，不必重写业务层。
- 与 G-001/G-004 的真机验证解耦，不被云服务阻塞。

**负面**

- MVP 不能跨设备同步/备份（需用户自行保留设备备份）。
- 后续接入 iCloud/后端需要迁移、账号、合规与成本评估。
- 立体声 96 kbps/声道音频体积大（约 2.07 GB/24h），未来全量同步不现实；需要“元数据/转写优先”的策略。
- 设备级 iCloud 备份会包含音频，2.07 GB/天；用户 iCloud 空间可能快速耗尽。
- 端上转写质量/速度受设备限制，混合路线要等后续版本。

**必须验证**

- MVP 网络审计：录音/转写期间无上传请求。
- 端上转写离线可用；无云密钥/配置。
- SwiftData 本地迁移与 FTS5 索引重建（ADR-0010）。
- 立体声 96 kbps/声道音频的 G-001/G-004（ADR-0011）。
- 设备级 iCloud 备份包含音频时的容量/恢复验证（Q-016）。

## 验证

- 在真机开启飞行模式完成录音、转写、检索、删除全流程。
- 用网络抓包/代码审查确认无音频/转写上传。
- 检查 Info.plist/entitlements 未启用 iCloud/CloudKit/Push（本地通知除外）。

## 回退

- 如果 MVP 需要跨设备：先评估 iCloud 元数据/转写同步（不含音频），新写 ADR；不得直接上传音频。
- 如果端上转写不可用：先降级为“仅录音 + 后续转写”，不要临时接入云 API。
- 如果未来上云：必须重新走隐私评估、App Store 披露与用户同意。
