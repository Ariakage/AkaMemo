# 测试策略

> 状态：活跃 · 最后更新：2026-10-28

## 1. 原则

- 测试证明行为，不证明实现。
- 核心链路（录音、分片、传输、删除、检索）优先于 UI 细节。
- 能在单元测试覆盖的逻辑，不依赖真机；只能在真机验证的场景，写成明确的手动矩阵。
- 测试不得使用真实用户录音、转写或个人信息。
- 不为让测试通过而降低产品行为；测试失败先判断是代码问题还是测试问题。

## 2. 测试层级

| 层级 | 运行环境 | 覆盖 | 速度 |
| --- | --- | --- | --- |
| 单元测试 | 模拟器 / `swift test` | 纯逻辑、状态机、格式化、分词、排序 | 快 |
| 集成测试 | 模拟器 | 文件落盘、数据库、索引、删除级联 | 中 |
| UI 测试 | 模拟器 | 关键流程导航与可见状态 | 慢，少量 |
| 真机手动测试 | iPhone + Watch | 录音、后台、中断、自动恢复、传输、GPS、5% 告警、诊断日志、电量/24h 续航 | 发布前必做 |

## 3. 测试 target

| Target | 内容 |
| --- | --- |
| `AkaMemoCoreTests` | 模型、状态机、校验和、去重、路径、检索分词、排序 |
| `AkaMemoTests` | iOS 集成：Inbox 校验、入库、删除级联、索引更新 |
| `AkaMemoWatchTests` | Watch 端分片写入、恢复扫描、传输队列状态 |
| UI 测试 | 首次同意、开始/停止、搜索、删除确认 |

## 4. 必须自动化的行为

**共享层**

- 分片命名与序号生成。
- 校验和计算与校验失败处理。
- 分片去重（同 ID + 同 checksum / 同 ID + 不同 checksum）。
- 会话/分片状态机合法与非法迁移。
- 时间戳转换（UTC ↔ 本地、绝对 ↔ 分片偏移）。
- 中文检索分词与查询（单字/双字/三字/中英混合）。
- 搜索结果排序与分页。
- 轨迹 JSONL 解析、GPX 生成与坐标范围校验。
- 电量阈值状态机、告警去重、通知内容构建。
- 心跳/看门狗状态机、自动恢复决策、缺口计算。
- 分片完整性校验、损坏隔离、manifest 重建。
- 日志脱敏、环形缓冲、文件轮转、导出过滤。
- SwiftData 迁移、FTS5 索引重建、分词查询。
- MVP 无云上传：网络审计/依赖扫描无云 STT/后端路径。
- 删除级联的元数据部分。

**iOS**

- Inbox 接收：完整文件、截断文件、校验和不匹配、重复文件。
- 音频入库：元数据 + 文件事务一致；索引失败不回滚音频，标记待重建，索引最终可重建/一致。
- 删除：音频、转写、索引、缓存全部移除；失败可重试。
- 转写队列：重启恢复、幂等、失败重试。
- 轨迹导入：重复、断行、时间倒序、坐标越界。
- GPX 导出：空轨迹、单点、跨时区、特殊字符。
- 通知权限拒绝、重复告警、Live Activity 启动/更新/结束状态。
- 中断检测、自动恢复、损坏隔离、通知去重。
- 诊断日志实时流、导出、清空、配额。
- 迁移：固定夹具库升级后实体与文件引用一致。

**Watch**

- 原子写入：模拟中断后不产生“完整”半截文件。
- 启动恢复：`.part`、损坏文件、manifest 不一致。
- 轨迹写入：追加、flush、崩溃后恢复。
- 心跳写入、看门狗判定、自动恢复尝试。
- 传输队列：重试退避、确认后清理、未确认不清理。

## 5. 测试夹具

- 音频：用代码生成正弦波/静音/白噪声，或使用明确授权的公开素材；夹具按立体声 96 kbps/声道 / 44.1 kHz（ADR-0011）生成。
- 单个夹具 **SHOULD** < 1 MB；大文件在测试运行时生成，不提交。
- 元数据夹具：固定 UUID、固定时间、固定路径，保证可重复。
- 数据库夹具：提交小型 `.sqlite` 或通过迁移脚本生成；不包含真实数据。
- 禁止：从用户设备导出的录音、转写、日志。

## 6. 真机验证

录音链路引用 `../specs/recording.md` 的验证矩阵；24h 续航引用 `../specs/24h-feasibility.md` 的 G-001；GPS 引用 `../specs/gps-tracking.md` 的 G-002；低电量告警引用 `../specs/battery-alerting.md` 的 G-003；保活/完整性引用 `../specs/recording-health.md` 的 G-004；诊断日志引用 `../specs/diagnostics.md` 的 G-005。

**待真机项集中维护在 [`device-testing-checklist.md`](device-testing-checklist.md)**；每次相关改动更新对应行，模拟器结果不得写成“通过”。每次涉及以下改动，必须重跑 P0 场景：

- 音频会话配置、格式、分片时长；
- 后台模式、Info.plist；
- 传输机制、确认与清理；
- 低电量/存储策略；
- 崩溃恢复与迁移。

记录模板见 `environment.md` §6。PR 中附：设备、系统版本、场景编号、结果、异常日志（脱敏）。

## 7. 命令

```bash
# 共享包（产物放本地磁盘，避开 iCloud 扩展属性）
swift test --package-path Packages/AkaMemoCore --scratch-path /tmp/AkaMemoCoreBuild

# iOS（统一使用 iPhone 18 Pro；同名设备有多个时改用 UDID）
xcodebuild test -project AkaMemo.xcodeproj -scheme AkaMemo \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro'

# watchOS
xcodebuild test -project AkaMemo.xcodeproj -scheme AkaMemoWatch \
  -destination 'platform=watchOS Simulator,name=<可用设备名>'

# 格式
xcrun swift-format lint --recursive AkaMemo AkaMemoWatch Packages
```

## 8. CI

- 工程创建后启用 GitHub Actions macOS runner。
- 必须通过：构建、单元测试、集成测试、`swift-format lint`。
- 可选：覆盖率报告、UI 测试（不稳定时先不阻塞合并）。
- 不在 CI 中签名、不跑真机、不存放密钥。
- 失败必须可复现；flake 测试需修复或隔离并建 issue。

## 9. 覆盖率

- `AkaMemoCore` 行覆盖率目标 ≥ 80%。
- 以下路径要求接近 100%：
  - 分片状态机；
  - 校验和/去重；
  - 删除级联；
  - 迁移；
  - 中文检索分词与查询。
- 不追求整体覆盖率数字；不为覆盖率写无断言测试。

## 10. 性能测试

- 搜索：10 万 segment，P95 < 200 ms。
- 分片写入：60 秒分片封口 < 500 ms（不含编码）。
- 启动恢复：1000 个分片扫描 < 2 s。
- 索引构建：1 万 segment < 30 s（测试机基线）。
- 诊断日志：1000 条渲染 P95 < 100 ms；音频回调无阻塞。
- 立体声 96 kbps/声道：24h 约 2.07 GB；分片封口/传输/索引按此规模测试。
- 性能测试结果记录设备与系统版本；回归超过 20% 需说明。

## 11. Flaky 测试

- 不允许长期存在 flaky 测试。
- 发现后：建 issue、标注负责人、在 2 个工作日内修复或隔离。
- 隔离必须显式（`XCTSkip` + issue 链接），不得删除断言。
- 不因 flaky 直接重跑直到通过而不记录。
