# 隐私与安全

> 状态：活跃 · 最后更新：2026-10-28
>
> 本文是录音、转写、日志、上传相关改动的强制检查依据。任何涉及数据流向的 PR 都必须对照本文。

## 1. 数据分类

| 数据 | 敏感级别 | 存储位置 | App 主动上传 | 系统备份可能包含 |
| --- | --- | --- | --- | --- |
| 原始录音 | 极高 | Watch / iPhone 本地 | 否 | 是（Q-016） |
| 转写文本 | 极高 | iPhone 本地 | 否 | 是 |
| GPS 轨迹 | 极高 | Watch / iPhone 本地 | 否 | 是 |
| 电量与告警状态 | 低 | 本地 / 通知 | 否 | 是（元数据） |
| Live Activity 状态 | 低 | iPhone 锁屏/灵动岛 | 否 | 否 |
| 诊断日志 | 中 | iPhone/Watch 本地 | 否 | 是 |
| 搜索索引 | 高 | iPhone 本地 | 否 | 是（可重建） |
| 会话元数据（时间、时长） | 高 | 两端本地 | 否 | 是 |
| 设备型号/系统版本 | 中 | 两端本地 | 否 | 是（元数据） |
| 崩溃日志/性能指标 | 中 | 本地/系统 | 仅在不含内容时可选上报 | 是（若开启） |
| 用户设置 | 低 | 本地 | 否 | 是 |
| 账号/身份信息 | — | MVP 不采集 | — | — |

> **“App 主动上传=否”不等于“绝不离开设备”**：iOS 设备级 iCloud 备份可能包含 App 数据（Q-016），由系统与用户控制。App 无法删除已生成的备份副本；删除只保证本地/当前数据，旧备份按 Apple 的备份轮转或用户删除策略处理。

**原则**：能不采集就不采集；能留在设备就不上传；必须上传时，最小化、可关闭、可删除。

## 2. 核心原则

1. **默认本地**：App 不主动上传录音与转写；系统 iCloud 备份可能包含 App 数据（Q-016），见 §4。
2. **显式同意**：任何上传、云端转写、分析上报都必须由用户主动开启，不得默认勾选。
3. **可见采集**：录音状态必须可见；不得隐蔽录音。
4. **最小权限**：只申请麦克风等必要权限；不申请通讯录、定位、照片等无关权限。
5. **真删除**：删除必须覆盖音频、转写、索引、缓存与本地副本。
6. **不训练**：不得将用户音频/转写用于模型训练，除非用户单独、明确同意。
7. **可审计**：设置中能看清数据流向；代码中数据路径可追溯。
8. **位置最小化**：只在录音会话期间记录位置；默认本地；导出前提示风险。

## 3. 同意与透明

### 3.1 首次启动

用户必须依次看到并确认：

- 应用做什么、录音存在哪里、默认不上传。
- 麦克风权限用途。
- 定位权限用途：仅在录音时记录位置，默认只存本机；可拒绝，录音仍可用。
- 首次授权后定位默认随录音开启；设置中可全局关闭；关闭后新会话不再采集。
- 通知权限（可选）：用于 5% 低电量告警；拒绝仍可使用，但没有系统通知。
- 如何暂停、如何删除全部数据（含位置轨迹）。
- 当地关于录音同意的法律提示（用户需自行确保获得对话方同意）。

未完成同意前，**MUST NOT** 启动录音或请求非必要权限。

### 3.2 录音可见性

- 录音中必须有持续可见的系统或应用内指示。
- 通知、实时活动、Watch 状态 **MUST** 与真实采集状态一致。
- 不得提供“隐藏录音”“伪装界面”“后台静默启动”等能力。
- “静默恢复”只关闭应用提示音/触觉；系统麦克风指示仍可见；不得后台无可见状态开麦。
- 默认不播放应用录音提示音（Q-017）；系统麦克风指示仍可见；用户需自行取得对话方同意。

### 3.3 权限文案

Info.plist 中的麦克风用途描述必须具体、真实，例如：

> AkaMemo 使用麦克风录制你主动开始的音频，用于在你的设备上生成可搜索的个人记忆。录音默认不会上传。

语音识别用途描述必须说明端上处理与不上传，例如：

> AkaMemo 使用 Apple 的端上语音识别把录音转成可搜索的文字。音频与转写文本不会离开你的设备。

**MUST NOT** 使用“为了改善服务”“提升体验”等模糊表述。

## 4. 存储与加密

- 使用 iOS/watchOS 文件保护：
  - 正在写入的分片/轨迹：`.completeUnlessOpen`；
  - 已封口分片、转写、索引、轨迹、GPX：`.completeUntilFirstUserAuthentication`。
  - 详见 `../architecture/data-model.md`。
- 密钥、令牌（如未来接入云端）存 Keychain，使用 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` 或更严格级别；**MUST NOT** 存 UserDefaults 或明文文件。
- 不自研加密算法；使用系统 CryptoKit / Security 框架。
- 日志与调试产物不得写入音频或转写内容。
- Q-016 已定：需要备份；MVP 不上云（无 CloudKit/后端），但允许 iOS 设备级 iCloud 备份包含音频/元数据。立体声 96 kbps/声道下 24h 约 2.07 GB，备份配额压力大；用户需自行管理 iCloud 空间。App 本身不上传。删除只保证本地与当前 App 容器；已生成的系统备份副本 App 无法单独删除，用户需通过 iCloud 备份设置/删除备份管理。

## 5. 传输与云端

**MVP 不上云**：不调用云转写、不接入自建后端、不启用 iCloud/CloudKit 同步；录音/转写/索引由 App 本地处理（ADR-0009）；系统备份例外见 §4。以下为后续版本的准入条件：

- 传输 **MUST** 使用 TLS 1.2+；禁止明文 HTTP。
- 云端存储 **MUST** 加密（传输中 + 静态）；密钥管理方案需 ADR。
- 云端转写 **MUST**：
  - 单独同意，明确服务商、地区、保留时长；
  - 提供“仅本地”替代；
  - 与服务商确认不用于训练；
  - 在隐私政策与 App Store 隐私标签中披露。
- 上传 **MUST** 可在设置中随时关闭；关闭后不得有后台重试上传。
- 位置轨迹默认不上传；GPX 导出是本地生成 + 系统分享，不是上传。
- 上传失败不得阻塞本地录音与管理功能。

## 6. 日志、分析与崩溃

- 使用 `OSLog`，敏感字段加 `privacy: .private`；发布版本关闭 debug 级日志。
- **MUST NOT** 记录：音频内容、转写文本、搜索词、文件名中的用户信息、经纬度、地址、轨迹内容、通讯录、账号标识。
- 诊断日志使用白名单 metadata；ID 截断；错误用错误码；默认 info，debug 需用户显式开启；文件 7 天/5MB；导出前提示；不上传。
- 允许记录：状态迁移、错误码、数量、耗时、设备型号（不含序列号）、系统版本。
- 分析/崩溃上报默认关闭；开启时必须：
  - 单独同意；
  - 不含内容与用户标识；
  - 提供关闭入口；
  - 在隐私文档中说明。
- 第三方 SDK 引入前必须做隐私评估并写 ADR；禁止引入会采集广告标识、联系人、位置的 SDK。

## 7. 保留与删除

| 数据 | 默认保留 | 用户可配置 |
| --- | --- | --- |
| 录音 | 直到用户删除（不自动删除，Q-013） | 否 |
| 转写 | 跟随录音；可只保留文本 | 是 |
| 索引 | 跟随录音/转写 | 否 |
| 位置轨迹 | 跟随录音 | 是（可单独删除） |
| GPX 导出缓存 | 导出后可清理 | 是 |
| 通知与 Live Activity | 系统临时展示，不落库 | 否 |
| 诊断日志 | 7 天 / 5MB，不含内容 | 是（可清空） |
| 崩溃报告 | 默认关闭 | 是 |

删除要求：

- 删除单条/单会话/全部数据都必须可用。
- 删除流程见 `../architecture/data-model.md`；任一步失败必须可重试，UI 不得提前显示“已删除”。
- Watch 本地副本、iPhone 本地副本、索引、缓存必须一起清除。
- 如果未来接入云端，删除必须传播到云端，并提供删除确认。

## 8. 法律与合规

> 以下是产品设计约束，不构成法律意见。上线前需由目标市场的法律顾问确认。

- **录音同意**：不同司法辖区对录音的同意要求不同（一方同意 vs 各方同意）。产品必须：
  - 在引导中提示用户需遵守当地法律并取得对话方同意；
  - 提供可见的录音指示；
  - Q-017 默认不提供应用录音提示音；在要求提示音/播报的市场，需重新评估合规性（可能不满足当地要求），并在上线前由法律顾问确认。
- **工作场所/学校**：不得宣传用于隐蔽监控员工、同学或他人。
- **位置数据**：轨迹可推断住址、工作地、宗教/医疗场所等敏感信息；需单独同意、最小化采集、默认本地、导出前提示。
- **未成年人**：MVP 不面向儿童；若涉及未成年人录音，需额外的监护人同意与合规评估。
- **GDPR/PIPL 等**：若引入云端或账号体系，需评估数据主体权利、跨境传输、敏感个人信息单独同意、数据本地化等要求。
- **App Store 审核**：持续录音、后台音频、麦克风权限都需要清晰的用户收益与可见指示；审核说明中必须解释“用户主动开始、可随时停止、默认本地”。

## 9. App Store 与平台合规

- `NSMicrophoneUsageDescription`：iOS 与 watchOS target 都必须配置，文案具体。
- `NSLocationWhenInUseUsageDescription`：说明“录音时记录位置，默认只存本机”；**MUST NOT** 申请 Always。
- Location Updates 后台模式与审核说明：解释“仅录音会话期间记录，可随时关闭”。
- 通知与 Live Activity：说明 5% 低电量告警用途；Time Sensitive 能力；MVP 不申请 Critical Alert，不得宣称“警报级”。
- Live Activity 不得用于广告或持续营销；低电量状态属于实时信息。
- 后台音频模式：仅声明实际使用的模式；审核说明中解释用途。
- `PrivacyInfo.xcprivacy`：按实际使用的 API 与数据填写；新增第三方 SDK 时同步更新。
- App Store 隐私标签：按“是否离开设备、是否与身份关联、是否用于追踪”如实填写。仅端上处理且不上传的数据，与云端可选路径的披露必须区分清楚；同时说明系统 iCloud 备份可能包含 App 数据（Q-016）。
- MVP 不上云：App 不主动上传；隐私标签需区分“App 上传=否”与“系统备份可能包含=是”，iCloud/后端/云转写均为后续版本，不得提前声明。
- 若使用加密（TLS 之外的自行加密），按要求完成出口合规声明。

## 10. 第三方依赖

新增依赖前必须评估：

- 许可证是否允许商业使用；
- 是否采集数据、是否包含分析/广告 SDK；
- 是否包含二进制闭源组件；
- 是否会访问麦克风、网络、文件系统；
- 是否可离线工作；
- 维护活跃度与安全记录。

评估结论写入 ADR；未评估的依赖不得合并。

## 11. 安全事件响应

1. **发现**：任何人发现疑似数据泄露、越权访问、日志含内容，立即停止相关功能并通知维护者。
2. **遏制**：关闭上传/分析开关，回滚相关版本，保留必要证据（不含用户内容）。
3. **评估**：影响范围、数据类型、受影响用户、法律义务。
4. **通知**：按适用法律与平台要求通知用户/监管；不得隐瞒。
5. **修复**：补测试、加防护、更新文档。
6. **复盘**：写 postmortem，记录根因与改进项；不追责个人。

## 12. PR 隐私检查清单

- [ ] 是否新增了数据采集、上传或第三方 SDK？
- [ ] 是否新增权限？用途文案是否具体？
- [ ] 日志/分析/崩溃中是否可能包含音频、转写、搜索词或用户标识？
- [ ] 删除路径是否覆盖音频、转写、索引、位置轨迹、GPX 缓存与副本？
- [ ] 是否新增定位采集？是否只在录音会话期间？是否可关闭？
- [ ] 定位默认开启时，设置中是否有清晰的全局关闭入口与状态展示？
- [ ] 通知/Live Activity 是否只含电量与录音状态，不含音频、转写、位置？
- [ ] 是否在通知/Live Activity 文案中错误宣称 Critical Alert/警报级？
- [ ] 静默恢复是否只关闭应用提示音/触觉，未隐藏系统指示或后台无可见状态开麦？
- [ ] 诊断日志是否脱敏、限额、导出前提示、不上传？
- [ ] MVP 是否意外引入了云转写/后端/iCloud 同步或上传路径？
- [ ] 设备级 iCloud 备份包含音频（Q-016）是否已在隐私说明中披露？
- [ ] 录音状态是否可见？是否存在静默启动路径？
- [ ] 云端路径是否可关闭？关闭后是否真的停止上传？
- [ ] 测试夹具是否使用合成音频/公开素材？
- [ ] 隐私文档、App Store 标签、`PrivacyInfo.xcprivacy` 是否同步？
- [ ] 是否更新了 `../decisions/` 中的相关决策？
