# 产品概览

> 状态：活跃 · 最后更新：2026-10-28
>
> 2026-10-28：Q-001 已确认采用 A（连续 24 小时不间断录音）；当前处于 G-001 可行性验证阶段，门禁通过前不得对外承诺 24h。见 `../decisions/0004-24h-recording-requirement.md` 与 `../specs/24h-feasibility.md`。

## 一句话

AkaMemo 把 Apple Watch 变成全天候的记忆入口：Watch 负责录音与轨迹，iPhone 负责整理、转写与回忆。

## 问题

日常对话、会议、课堂、通勤中的灵感，大部分在发生后几分钟内就消失。手机录音需要主动掏出设备、解锁、开始录制；专业录音笔则需要额外携带和充电。Apple Watch 一直在手腕上，是唯一可能做到“抬手就记、放下就忘”的设备。

现有方案的缺口：

- 手机录音启动成本高，事后整理更少。
- 录音笔需要额外设备、同步麻烦、容易忘记佩戴。
- 语音备忘录类应用偏“单次录制”，不面向全天候、可检索的个人记忆。
- 云端常听设备隐私风险高，用户无法确认数据去向。

## 目标用户

**主要用户**

- 需要频繁记录会议、访谈、课堂的学生与知识工作者。
- 有大量碎片灵感、口头待办的创作者与创业者。
- 希望“事后能找回说过什么”的个人用户。

**不是目标用户**

- 需要企业级合规审计、集中管理的团队（MVP 不做管理后台）。
- 希望在他人不知情的情况下进行隐蔽录音的用户（产品明确禁止）。
- 需要专业音频制作、多轨录音的用户。

## 核心场景

1. **会议/课堂**：抬手开始录音，结束后在 iPhone 上转写、搜索关键结论。
2. **通勤/散步**：想到什么说什么，晚上按时间线回看当天记录。
3. **日常对话**：答应别人的事、临时信息，事后用关键词找回。
4. **采访/调研**：长时间录音，分片传输，转写后按时间定位原声。
5. **出行/旅行**：录音同时记录轨迹，事后按地点与时间回看当天经历。

## 产品原则

1. **隐私默认**：App 不主动上传录音/转写；系统 iCloud 备份可能包含音频（Q-016）。上传/备份范围必须透明、可关闭。
2. **不丢音频**：先落盘再传输；分片、校验、幂等、断点续传优先于“实时”。
3. **全天候可用**：真实佩戴、真实电量、真实中断场景下的可靠性优先于功能数量。
4. **可检索**：录音只是原料，转写与检索才是产品价值。
5. **可删除**：用户必须能看见、暂停、删除每一段录音及其派生数据。
6. **不欺骗**：录音状态必须可见；不做隐蔽录音；不把“云端”伪装成“本地”。
7. **位置最小化**：只在录音会话期间记录位置；默认本地；导出前提示风险。
8. **可诊断**：录音中断、损坏、恢复都要有状态与日志，不静默失败。
9. **MVP 不上云**：音频、转写、索引由 App 本地处理；混合转写、iCloud、自建后端为后续版本；系统备份例外见隐私文档。

## MVP 范围

**MVP 不上云**：音频、转写、索引由 App 本地处理；不集成云 STT、自建后端或 iCloud/CloudKit 同步；系统备份例外见隐私文档。

**包含**

- Watch 端录音：前台启动、后台延续、中断可恢复；目标连续 24 小时（G-001 门禁）。
- 录音期间记录 GPS 轨迹，并支持按需导出 GPX（G-002 门禁）。
- Watch 电量 5% 时向 iPhone 发高优先级通知，并在低电量期间显示 Live Activity/灵动岛（G-003 门禁）。
- 录音保活、中断通知、自动恢复与完整性校验（G-004 门禁）。
- 实时诊断日志（G-005 门禁）。
- 录音分片、落盘、崩溃恢复。
- 分片可靠传输到 iPhone，幂等、可重试。
- 端上转写（MVP 不上云；混合/云端为后续版本，见 ADR-0009）。
- 全文检索、按时间浏览、播放定位。
- 录音与派生数据的删除、保留策略。
- 首次启动的知情同意与权限引导。

**前置门禁**

- G-001 连续 24 小时可行性验证；若启用 GPS，还需 G-002；低电量告警需 G-003；录音保活/完整性需 G-004；诊断日志需 G-005。未通过则 MVP 范围与对外承诺需重新确认，见 ADR-0004～ADR-0008。

**不包含**

- AI 总结、每日回顾、对话式回忆。
- 说话人分离、情绪识别、关键词自动标签。
- 多端同步、Web 端、团队协作。
- 云端转写、自建后端、iCloud/CloudKit 同步（MVP 不上云）。
- 音频/转写导出（Q-014 不做；GPX 导出保留）。
- 远程推送/APNs 与 Critical Alert（MVP 不申请）。
- 端到端加密的云端备份（未来可选）。
- Android / 非 Apple 平台。

## 成功指标

MVP 阶段只看少数几个能反映“是否真的可用”的指标：

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 分片丢失率 | 0 | 从 Watch 落盘到 iPhone 入库，不允许静默丢失 |
| 连续 24 小时录音 | G-001 通过 | 音频连续、0 丢失/损坏、设备未关机；见 `../specs/24h-feasibility.md` |
| GPS 轨迹覆盖与精度 | G-002 通过 | 5min 采样；缺口 ≤6min；精度中位数 ≤ 30m；见 `../specs/gps-tracking.md` |
| 5% 告警送达 | G-003 通过 | iPhone 可达时 60s 内收到 Time Sensitive 通知；见 `../specs/battery-alerting.md` |
| 已封口分片损坏率 | 0 | 断电/被杀损失 ≤ 60 秒；见 `../specs/recording-health.md` |
| 中断通知 | G-004 通过 | 中断后 30s 内状态可见，60s 内通知（iPhone 可达） |
| 录音可恢复率 | ≥ 99% | 中断/崩溃/重启后能继续或找回已录内容 |
| 转写完成率 | ≥ 95% | 已传输分片在 24h 内完成转写（充电 + Wi‑Fi 条件下） |
| 搜索响应 | P95 < 200 ms | 1 万条分片规模 |
| 24h 音频体积 | ≤ 2.2 GB | 立体声 96 kbps/声道 / 44.1 kHz；见 ADR-0011 |
| 电池消耗 | 待实测 | 连续录音每小时耗电百分比，见 `specs/recording.md` |
| 崩溃率 | crash-free ≥ 99.5% | 按会话统计 |

指标目标会随真机基线调整；调整时更新本表并注明日期。

## 关键风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Apple Watch 电池无法支撑 24h 连续录音 | 产品核心承诺不成立 | Q-001 已确认 A；先执行 G-001 真机门禁；未通过按 ADR-0004 评估降级/外接电源，不得对外承诺 |
| GPS 连续定位加剧耗电与隐私风险 | 24h 组合目标失败；位置泄露 | 采样降频、低电量策略、默认本地、导出前提示；G-002 门禁 |
| 低电量告警无法保证即时/警报级 | 用户错过充电窗口 | Time Sensitive 通知 + Watch 本地警告；Live Activity 前台/点击启动；不承诺后台自动或 24h 常驻；G-003 门禁 |
| 录音中断/损坏 | 用户丢失记忆、信任下降 | 60 秒分片、心跳/看门狗、自动恢复、完整性校验、异常通知；G-004 门禁 |
| 诊断日志泄露内容 | 隐私风险 | 脱敏、默认 info、7 天/5MB、不上传；G-005 门禁 |
| 立体声 96 kbps/声道体积与功耗 | 24h 约 2.07 GB；30 天约 62 GB；Watch 存储/传输/电量压力大 | G-001/G-004 用最终参数验证；失败时由用户决定降码率/外接电源，不得静默降级；见 ADR-0011 |
| iCloud 备份空间 | 2.07 GB/天，iCloud 空间可能快速耗尽 | Q-016 需要备份；在隐私说明中披露；用户自行管理空间 |
| watchOS 后台录音限制 | 退到后台/中断后无法自动恢复 | 前台启动 + 后台音频延续 + 分片落盘；可恢复场景自动重试，失败后前台触发；见 `specs/recording.md`、`specs/recording-health.md` |
| App Store 审核对持续录音的审查 | 无法上架 | 录音指示可见、知情同意、隐私政策、审核说明；见 `privacy/privacy-and-security.md` |
| 转写质量不足 | 检索价值下降 | 引擎可替换；建立中文基线评测；低置信度标记 |
| 隐私事件 | 信任崩塌、法律风险 | 默认本地、最小权限、真删除、日志脱敏、事件响应流程 |
| 存储增长 | 设备空间不足 | 码率与保留策略可配置；Watch 只保留未传输分片 |

## 开放问题

`Q-001`～`Q-023` 已全部关闭；完整决策见 `decisions/README.md`。

实现前仍需用真机/基准确认的假设：

- **96 kbps 已确认按每声道计算**（ADR-0011）；立体声合计 192 kbps，24h ≈2.07 GB。
- **Apple Watch 是否暴露立体声/多声道**：按实际 `channelCount` 记录，不伪造；若只有单声道，更新体积基线。
- **G-001～G-005**：24h、GPS、低电量、保活/完整性、诊断日志均未真机验证。
- **Q-016**：iCloud 备份包含音频，2.07 GB/天；备份恢复与空间管理需验证。

G-001～G-005 通过前，工程可以按目标设计，但不得对外承诺 24h 连续录音、24h + GPS、自动灵动岛/警报级或“绝不丢失/绝不损坏”；未通过时按对应 ADR 由用户决定降级方案。

## 术语

| 术语 | 含义 |
| --- | --- |
| 会话（Session） | 一次用户主动开始、停止的录音过程，可跨多个分片 |
| 分片（Chunk） | 录音的最小落盘与传输单位，默认 60 秒 |
| 转写（Transcript） | 一个分片对应的文字结果，含时间戳片段 |
| 记忆条目（Memory） | 用户在 iPhone 上看到的一天/一次会话的时间线视图，MVP 中由会话与转写派生，不单独存储 |
| 轨迹（Track） | 录音会话期间记录的位置点序列，存为 JSONL |
| GPX | 通用 GPS 轨迹交换格式，导出时生成 |
| Live Activity | iOS 锁屏/灵动岛的实时状态卡片；本产品用于低电量录音状态 |
| 心跳 / 看门狗 | Watch 定时上报录音健康状态；看门狗检测静默停止 |
| 诊断日志 | 应用内实时结构化日志；默认不含音频/转写/位置 |
