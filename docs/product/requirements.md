## 编号与优先级

- `FR-xxx`：功能需求；`NFR-xxx`：非功能需求；`AC-xxx`：验收标准；`Q-xxx`：开放问题（见 `../decisions/README.md`）。
- 优先级：**P0** = MVP 必须；**P1** = MVP 应该；**P2** = 后续版本。
- 规范级别：**MUST / SHOULD / MAY**（RFC 2119）。

## 用户故事

- 作为用户，我可以在 Watch 上抬手开始录音，锁屏或放下手腕后录音继续。
- 作为用户，我可以在 iPhone 上看到今天录了什么，并按关键词找回某句话。
- 作为用户，我可以删除一段录音，并确信相关转写和索引也一起消失。
- 作为用户，我可以在首次使用时清楚知道录音存在哪里、谁会看到、如何关闭。
- 作为用户，我希望录音时记录位置并能导出 GPX，以便回忆“在哪里说了什么”。
- 作为用户，我希望 Watch 电量降到 5% 时 iPhone 能提醒我，并在低电量期间看到录音状态。
- 作为用户，我希望录音中断时收到通知、能自动恢复，并能查看实时诊断日志。

### FR-001 首次启动知情同意与权限引导（P0）

用户第一次打开 iPhone 或 Watch 应用时，**MUST** 依次看到：

1. 产品做什么、录音存在哪里、默认不上传。
2. 麦克风与定位权限用途说明；分别请求权限（定位可跳过，录音仍可用）。首次授权定位后，默认随录音开启，可在设置中全局关闭。
3. 录音指示与暂停方式；如何删除全部数据。
4. 通知权限（可选）：说明 5% 低电量告警；拒绝仍可使用，但无系统通知。
5. 明确同意后才能开始录音。

**AC-001**

- Given 用户首次安装且未同意，When 点击“开始录音”，Then 不启动录音，并回到同意页。
- Given 用户拒绝麦克风权限，When 再次进入应用，Then 显示权限被拒的原因与前往设置的入口。
- Given 用户同意，When 完成引导，Then 同意状态持久化，后续启动不重复完整引导。

### FR-002 麦克风权限拒绝后的降级与恢复（P0）

- 权限被拒时，**MUST** 禁用录音入口并说明原因，不得闪退或静默失败。
- 用户从系统设置恢复权限后，回到应用 **MUST** 自动恢复可用状态，无需重启。

### FR-003 Watch 开始/停止录音（P0）

- 用户 **MUST** 能在 Watch 前台一键开始录音。
- 用户 **MUST** 能在 Watch 前台停止录音；停止后当前分片立即封口并进入传输队列。
- 录音启动 **MUST** 在用户可见的前台交互中发生；不得由后台任务、通知或定时器静默启动。
- 启动失败时 **MUST** 给出可理解的错误与重试入口。

**AC-003**

- Given Watch 应用在前台且权限已授予，When 点击开始，Then 1 秒内出现录音中状态，并产生第一个可播放分片（默认 60 秒内可提前封口）。
- Given 正在录音，When 点击停止，Then 录音状态结束，当前分片完成校验并进入待传输队列。

### FR-004 后台持续录音（P0）

- 录音开始后，用户放下手腕、锁屏、切换到其他应用，录音 **MUST** 按平台允许的方式继续；产品目标为连续 24 小时（见 G-001）。
- 来电、Siri、音频路由变化等中断发生时，**MUST** 立即封口当前分片；恢复策略见 `../specs/recording.md`。
- 系统强制终止后，已落盘分片 **MUST** 在下次启动时可被发现并恢复。
- 在平台能力不允许自动恢复的场景，**MUST** 明确提示用户需要回到前台继续，不得假装仍在录音。

**AC-004**

- Given 录音中，When 屏幕熄灭 10 分钟，Then 期间音频连续，分片按时封口。
- Given 录音中，When 来电并挂断，Then 当前分片已落盘；应用回到前台后提示用户是否继续录音。
- Given 录音中，When 应用被系统杀死，Then 重启后能扫描到已落盘分片并继续传输。
- Given G-001 门禁通过，When 连续录音 24 小时，Then 音频连续、分片 0 丢失/0 损坏、设备未关机。

### FR-005 录音状态可见（P0）

- Watch 与 iPhone **MUST** 能明确显示：正在录音、已暂停、正在传输、传输失败。
- 录音中 **MUST** 有系统录音指示或等效的持续可见标识；不得隐藏。
- 通知/实时活动（如使用）**MUST** 与真实状态一致，不得出现“显示录音但实际未录”的情况。
- 默认不播放应用录音提示音（Q-017）；系统麦克风指示仍可见；用户需自行取得对话方同意；可选提示后续再评估。

### FR-006 分片落盘与崩溃恢复（P0）

- 音频 **MUST** 以分片为单位原子写入：先写临时文件，校验后 rename。
- 每个分片 **MUST** 有元数据：会话 ID、**所属会话开始时间 `sessionStartedAt`**、序号、分片开始时间、时长、字节数、校验和、格式版本、声道数。
- 原始多声道 AAC **MUST** 保留；录音链路 **MUST NOT** 做降混/降噪（Q-006）；后期处理另行。
- 录音链路 **MUST NOT** 静默改变采样率/码率/声道/分片参数；低功耗档位必须由用户显式选择并递增 `formatVersion`。
- 实际不可用多声道时，按硬件/API 记录真实 `channelCount`，不得伪造多声道。
- 启动时 **MUST** 扫描未完成分片：可修复则修复，不可修复则标记为损坏并在 UI 可见。
- manifest **MUST** 记录 `localState`（present/reclaimed/deleted/audioPurged/missing）与墓碑关联；正常清理（已确认回收/用户删除/音频清理）不得误报为 `missing`。
- 分片索引 **MUST** 原子更新，不得因崩溃产生半截 JSON。

### FR-007 分片传输与幂等（P0）

- Watch → iPhone 的传输 **MUST** 使用适合后台上传的文件传输机制，不得使用不可靠的即时消息通道传音频。
- iPhone 接收端 **MUST** 先检查 `DeletionTombstone`，命中则丢弃并回执删除；未命中才按分片 ID 去重。
- 传输失败 **MUST** 指数退避重试；用户可手动重试。
- 允许蜂窝网络传输（Q-008）；用户可限制仅 Wi-Fi。
- 传输顺序不保证时，iPhone **MUST** 能按会话与序号重组时间线。

### FR-008 传输确认与 Watch 空间回收（P0）

- 只有 iPhone 完成校验并确认手机文件可读/完整后，Watch **MAY** 删除本地分片（Q-014）。
- 删除 **MUST** 分两阶段：标记已确认 → 延迟清理；保留窗口内可再次补传。
- Watch **MUST** 在空间不足时优先清理已确认分片，不得删除未确认分片。
- 已墓碑化的分片 **MUST NOT** 进入传输队列；已排队条目 **MUST** 清除。

### FR-009 转写入库（P0）

- 已校验分片 **MUST** 进入持久化转写队列；应用重启后队列可恢复。
- MVP **MUST** 仅使用端上转写；**MUST NOT** 调用云 STT 或上传音频/转写；混合/云为后续版本（ADR-0009）。
- 转写前 **MUST** 将多声道降混为单声道并重采样到 16 kHz（ADR-0011）。
- MVP **MUST** 至少支持普通话与英语；其他语言按端上引擎能力启用（Q-015）。
- 转写结果 **MUST** 包含分段与时间戳，能映射回音频位置。
- 转写失败 **MUST** 可重试，并保留失败原因（不含音频内容）。
- 同一分片 + 同一引擎版本 **MUST** 只成功转写一次；重复执行结果幂等。
- 转写任务开始前与提交前 **MUST** 检查墓碑/DataEpoch；删除时 **MUST** 取消任务，删除后完成的结果不得写回转写或索引。

### FR-010 全文检索（P0）

- 用户 **MUST** 能按关键词检索转写文本，结果按时间或相关度排序。
- 结果 **MUST** 显示命中片段、时间、所属会话，并可跳转到对应音频位置。
- 中文检索 **MUST** 支持连续中文子串命中，不能只按空格分词。
- 短查询（1–2 个汉字/字符）**MUST** 通过独立的 short-token 索引命中；不得因 trigram 的 3 字符限制返回空结果。
- 空结果 **MUST** 有明确提示，不得显示空白页。
- 索引写入失败 **MUST NOT** 回滚已入库的音频/转写；标记待重建，最终可重建一致。

### FR-011 录音列表与播放（P0）

- iPhone **MUST** 按天/会话展示录音，显示时长、转写状态、传输状态。
- 用户 **MUST** 能播放、暂停、拖动进度；拖动后时间显示与音频位置一致。
- 转写片段与播放进度 **SHOULD** 联动高亮。
- iPhone **MUST NOT** 声明 Audio 后台模式；MVP 不要求后台播放/锁屏控制（Q-018）。

### FR-012 删除与保留（P0）

- 删除粒度 **MUST** 明确：单条分片（`chunk`，只删该分片音频/转写/索引，不影响同会话其他分片/轨迹）、单次会话（`session`，级联全部）、全部数据（`all`）；不得把 `chunk` 删除扩大为 `session` 删除。
- 删除 **MUST** 先写入 `DeletionTombstone`（全量删除写 `DataEpoch`），再删本地数据；墓碑至少保留到 Watch 确认 + 宽限期。
- 删除指令 **MUST** 携带 `scope` 与对应 ID；Watch 只删除匹配范围。
- “删除全部数据” **MUST** 用 `DataEpoch = now` 覆盖 Watch 上所有 `sessionStartedAt < epoch` 的会话，包括 iPhone 未知的离线会话；**仅当当前录音会话的 `startedAt < epoch`** 时才停止/封口并删除；新会话不得停止或删除。
- iPhone Inbox **MUST** 拒绝 `sessionStartedAt < DataEpoch` 的分片，即使没有逐实体墓碑；分片元数据必须携带 `sessionStartedAt`。
- 删除 **MUST** 同时删除音频分片、转写、索引、位置轨迹、GPX 缓存与 Watch 本地副本；不得只删数据库记录。
- iPhone **MUST** 通过 WatchConnectivity 发送删除指令（含 tombstoneID/sessionID）并等待回执；Watch 离线时墓碑持久化，重连后补发。
- iPhone Inbox **MUST** 拒绝任何已墓碑化的 session/chunk；迟到分片必须丢弃并回执删除，不得重新创建记录。
- Watch 本地传输队列中的已墓碑化分片 **MUST** 在发送前/发送中取消，不得继续传输。
- 删除 **MUST** 幂等；重复删除/重复回执不得报错或复活数据。
- 删除操作 **MUST** 有二次确认；删除后 **MUST** 不可恢复（除非用户显式使用系统备份）。系统备份恢复到删除前快照可能带回旧数据，App **MUST** 提示并允许再次删除。
- 默认保留策略 **MUST** 是“保留直到用户删除”；MVP **MUST NOT** 自动删除（Q-013）。

**AC-012**

- Given Watch 离线时删除会话，When 重新连接，Then 删除指令送达，Watch 分片删除并回执；iPhone 不重建记录。
- Given 删除后收到迟到分片，When Inbox 处理，Then 丢弃并回执，不创建记录。
- Given 重复删除，When 再次执行，Then 幂等成功，不复活数据。
- Given Watch 离线且有 iPhone 未知会话，When 执行“删除全部”，Then 重连后 epoch 应用、旧会话删除且不导入。
- Given 删除时转写任务在运行，When 任务完成，Then 不写回转写/索引。
- Given 清理音频，When 完成，Then 音频删除、转写可搜索、Watch 不补传。
- Given 删除单个分片，When 完成，Then 同会话其他分片/轨迹保留，不得扩大为 session 删除。
- Given 离线 Watch 在 epoch 之后开始新录音，When 收到延迟的全量删除指令，Then 新会话不停止、不删除。
- Given 长会话跨越 epoch，When Inbox 收到 epoch 之后生成的分片，Then 按 sessionStartedAt 判定为旧会话并拒绝。
- Given 删除轨迹后 Watch 重连，When 补传轨迹，Then TrackImporter 拒绝且不重建。

### FR-013 低电量与低存储策略（P0）

- 电量策略 **MUST** 按以下阈值执行：20% 应用内提示；10% 强提示并降低 GPS 采样；**5% 发送 iPhone 高优先级通知并启动/更新 Live Activity**；3% 安全停止并封口当前分片。
- 5% 时只告警并继续录音；3% 时自动安全停止；MVP 不提供 5% 自动暂停。
- 存储低于安全阈值时，**MUST** 停止新录音并提示清理；已录分片不得被新数据覆盖。
- 阈值与告警行为见 `../specs/battery-alerting.md`；录音侧阈值见 `../specs/recording.md`。

### FR-014 存储管理（P1）

- 用户 **MUST** 能看到音频、转写、索引分别占用多少空间。
- 用户 **MAY** 清理音频并保留转写文本（需明确提示后果）。
- 清理音频 **MUST** 只删音频文件，保留 Transcript/索引/元数据；写 `entityType=audio` 墓碑；Watch **MUST NOT** 补传该音频，Inbox **MUST** 拒绝音频但保留转写。
- “删除整个会话”是 `session` 级墓碑，级联删除音频/转写/索引/位置；“删除单个分片”是 `chunk` 级墓碑，只删该分片；二者与“清理音频”语义不同。

### FR-015 设置（P1）

- 设置 **MUST** 包含：录音开关/提示、语言（MVP 普通话+英语）、低电量阈值、传输网络条件、转写引擎（MVP 仅端上；后续可选）、自动恢复录音、静默恢复、诊断日志、保留策略、删除全部数据。
- “静默恢复”只关闭应用提示音/触觉，**MUST NOT** 隐藏系统麦克风指示或允许后台无可见状态开麦。
- 设置项变更 **MUST** 立即生效或明确说明需要重启。

### FR-016 暂停与隐私快捷操作（P1）

- 用户 **MUST** 能从 Watch 快速暂停/恢复录音。
- 暂停期间 **MUST** 不产生音频数据；恢复后开始新分片。
- 暂停状态 **MUST** 在两端可见。

### FR-017 转写重试与引擎切换（P1）

- 用户 **MAY** 对失败分片手动重试。
- 切换转写引擎 **MUST** 不删除旧结果；新旧结果可对比或由用户选择保留。

### FR-018 搜索高亮与跳转播放（P1）

- 点击搜索结果 **MUST** 跳转到对应会话与时间点，并高亮命中文本。
- 若音频已被清理但转写仍在，**MUST** 显示转写并说明音频不可用。

### FR-019 无障碍（P1）

- 所有关键操作 **MUST** 支持 VoiceOver 与 Dynamic Type。
- 录音状态 **MUST** 不只依赖颜色表达。
- 播放/暂停/删除控件的可点击区域 **MUST** 满足平台最小值。

### FR-020 音频/转写导出（不做，Q-014）

- MVP **MUST NOT** 提供音频/转写导出/分享；只做 Watch→iPhone 自动同步、校验手机文件后删除 Watch 文件。
- GPX 轨迹导出仍保留（FR-022 / Q-021）。

### FR-021 录音期间记录 GPS 轨迹（P0）

- 在用户授权定位后，录音会话期间 **MUST** 记录位置轨迹，并与会话关联。
- 采样 **MUST** 为高精度、低频率：每 5 分钟一个点（Q-019）；低电量/热状态可降精度但保持 5 分钟。
- 首次授权后，定位 **MUST** 默认随录音开启；设置中 **MUST** 可全局关闭；**MUST NOT** 每次询问。
- 轨迹导出 **MUST** 按选中会话/片段的开始与结束时间裁剪（Q-021）。
- 使用 When In Use 授权；**MUST NOT** 请求 Always（watchOS 不可用）。
- 拒绝定位时录音 **MUST** 继续，轨迹状态为 `unavailable`，UI 明确提示。
- 录音暂停时暂停定位；恢复时继续。
- 轨迹默认本地存储，不上传；采样、精度与降级见 `../specs/gps-tracking.md`。
- 删除录音时 **MUST** 级联删除轨迹与 GPX 缓存。

**AC-021**

- Given 已授权定位且户外移动，When 录音 30 分钟，Then 生成轨迹 JSONL，时间戳单调，点数符合采样策略。
- Given 首次授权定位，When 开始录音，Then 默认记录轨迹；When 在设置中全局关闭，Then 后续录音不再采集。
- Given 拒绝定位，When 录音，Then 录音正常，轨迹 `unavailable`，UI 提示可在设置开启。
- Given 室内无信号，When 录音，Then 轨迹 `degraded` 或为空，录音不中断。

### FR-022 GPX 导出（P0）

- 用户 **MUST** 能按会话导出 GPX 1.1，并按会话/片段的**开始与结束时间裁剪**。
- 导出前 **MUST** 显示隐私提示：GPX 会暴露行踪，分享前请确认。
- 文件名与内嵌名称 **MUST NOT** 包含地点、地址或用户内容。
- 导出通过系统分享面板完成；应用 **MUST NOT** 自动上传。

**AC-022**

- Given 有轨迹的会话，When 导出 GPX，Then 文件可被常见 GPX 查看器解析，时间 UTC、坐标 WGS84。
- Given 轨迹为空，When 导出，Then 明确提示无轨迹，不生成空文件。

### FR-023 轨迹查看（P1）

- iPhone **SHOULD** 在地图上展示会话轨迹，并与录音时间轴联动。
- 无轨迹或轨迹降级时 **MUST** 说明原因，不显示空白地图。

### FR-024 定位隐私控制（P0）

- 用户 **MUST** 能在设置中全局关闭定位；默认开启状态 **MUST** 清晰可见。
- 关闭后 **MUST** 立即停止当前会话的定位采集，并且新会话不采集；已存在轨迹保留，除非用户删除。
- 按会话关闭为 P1 可选（例如录音前的临时开关），不阻塞 MVP。
- 设置中 **MUST** 显示定位权限状态与轨迹占用空间。
- 删除轨迹 **MUST NOT** 删除录音；删除录音 **MUST** 删除轨迹。
- 删除轨迹 **MUST** 写 `DeletionTombstone(entityType=location)`；Watch 删除轨迹且不得补传。
- `TrackImporter` **MUST** 同时检查 session 墓碑、location 墓碑与 `DataEpoch`（`sessionStartedAt < epoch`）；任一命中则拒绝并回执，不得重建；轨迹元数据必须携带 `sessionStartedAt`。
- 重连测试覆盖轨迹补传被拒绝。

### FR-025 5% 低电量 iPhone 通知（P0）

- Watch **MUST** 先设置 `WKInterfaceDevice.current().isBatteryMonitoringEnabled = true` 再读取电量；未启用/未知时 **MUST** 显示“电量监测不可用”并记录，不得静默跳过告警。
- Watch 电量降到 5% 时，**MUST** 通过 WatchConnectivity 通知 iPhone；iPhone **MUST** 发 Time Sensitive 本地通知。
- 通知 **MUST** 在 60 秒内送达（iPhone 可达时）；同一次跨阈值只发一次。
- 消息 **MUST** 带 `eventID`、`recordedAt`、TTL；`stateVersion` 仅作快照上下文，**MUST NOT** 用于告警事件排序。
- 告警 **MUST** 按 `eventID` 去重 + TTL + 处理时刻最新快照判断有效性；不得因更高版本心跳先到而丢弃仍在 TTL 内、状态仍为 5%/录音中的未处理告警。
- 过期或最新快照已停止/充电/3% 时，不得补发“录音仍在继续”或启动过时 Live Activity。
- 通知内容 **MUST** 只含电量、录音状态、时间；**MUST NOT** 含音频、转写、位置。
- 通知权限被拒时，**MUST** 在 App 内与 Watch 端显示警告，不得静默失败。
- **MVP MUST NOT 申请 Critical Alerts entitlement**；统一使用 Time Sensitive。后续如需再评估，必须新写 ADR。

**AC-025**

- Given Watch 5% 且 iPhone 可达，When 触发，Then 60 秒内收到 Time Sensitive 通知，内容正确。
- Given 通知权限被拒，When 触发，Then 应用内与 Watch 警告可见。
- Given 重复消息，When 处理，Then 不重复通知。
- Given 离线期间积压的 5% 消息，When 重连时录音已停止/充电，Then 丢弃过期消息，不补发“录音仍在继续”或启动 Live Activity。
- Given 5% 告警 v7 仍在 TTL 内，When 心跳 v8 先到且最新状态仍为 5%/录音中，Then 仍处理 v7 告警。

### FR-026 低电量 Live Activity / 灵动岛（P0）

- App 在前台收到 5% 状态时，**MUST** 启动/更新 Live Activity。
- App 在后台时，**MUST** 先发通知；用户点击通知打开 App 后 **MUST** 先重新读取最新状态，未过期且录音仍在继续才启动。
- 点击旧通知时，TTL 过期、录音已停止或充电 >10% **MUST NOT** 启动 Live Activity，只显示当前状态。
- Live Activity **MUST** 显示电量、录音状态、时长；**MUST NOT** 显示音频、转写、位置。
- 8 小时系统上限后 **MUST** 正常结束，不得崩溃；不得承诺 24h 常驻。
- 不支持灵动岛/Live Activity 的设备 **MUST** 降级为通知 + 应用内横幅。

**AC-026**

- Given App 前台 5%，When 触发，Then Live Activity 显示。
- Given App 后台 5%，When 用户点击通知且状态仍有效，Then App 打开并启动 Live Activity。
- Given 用户数小时后点击旧通知且录音已停止/充电，Then 不启动 Live Activity，只显示当前状态。
- Given 录音停止/充电 >10%，When 状态变化，Then Live Activity 结束。

### FR-027 低电量自动暂停策略（P0）

- 5% 时只告警并继续录音；MVP 不提供 5% 自动暂停选项。
- 3% 时 **MUST** 自动安全停止：封口当前分片 → 暂停 → 尝试通知。
- 3% 停止 **MUST NOT** 丢失已录分片；恢复充电后不得自动开始录音。

**AC-027**

- Given 5%，When 继续录音，Then 录音保持，告警已发。
- Given 3%，When 触发，Then 当前分片封口并暂停，UI 显示原因。

### FR-028 录音保活与异常通知（P0）

- Watch **MUST** 持续监测音频回调/心跳；10 秒无数据尝试恢复，30 秒无数据标记中断。
- 中断 **MUST** 在 Watch 与 iPhone 上可见；Watch 存活且 iPhone 可达时 60 秒内通知。
- Watch 进程消失/不可达时，iPhone 已收到心跳则 **MUST** 在 90 秒内发“无法确认录音状态”本地通知（dead-man's switch）；iPhone 被强制退出/从未收到心跳时不保证送达，必须说明。
- 心跳与电量 **MUST** 合并为单一 `applicationContext` 快照，不得互相覆盖。
- dead-man 通知 **MUST** 仅在 recording 状态调度；stop/pause/finalize/delete/all-data **MUST** 取消 pending 通知；resume 时重新调度。
- `stateVersion` **MUST** 在同一会话内跨重启单调递增，不得归零；新会话用新 `sessionID` 从 1 开始。
- 通知内容只含状态/时间/错误码；**MUST NOT** 含音频、转写、位置。
- 预期暂停/用户停止 **MUST NOT** 触发中断通知。

**AC-028**

- Given 录音中，When 音频回调停止 30 秒，Then 状态 `interrupted`，封口分片，通知。
- Given Watch 进程消失且 iPhone 已收到心跳，When 90 秒无心跳，Then 收到“无法确认”本地通知。
- Given 心跳与电量同时更新，When 写 applicationContext，Then 两者都在同一快照中，不互相覆盖。
- Given 正常停止/暂停/删除，When 状态结束，Then pending dead-man 通知被取消。
- Given Watch 重启后继续同一会话，When 发 stateVersion，Then 版本继续递增且不归零。
- Given 用户主动停止，When 状态结束，Then 不触发中断通知。

### FR-029 录音自动恢复（含静默恢复）（P0，2026-10-28 边界已确认）

- 可恢复场景（App 仍持有音频会话/后台音频执行）**MUST** 最多尝试 3 次（1s/5s/15s）；成功新开分片并记录 gap；失败标记中断。
- 设置 **MUST** 提供“自动恢复录音”和“静默恢复”；“静默”仅指不播放应用提示音/触觉，系统麦克风指示仍可见。
- App 被杀/重启后 **MUST** 只在前台恢复：3 秒倒计时可取消，或手动恢复。
- **MUST NOT** 隐藏系统麦克风指示、伪造未录音状态或在后台无可见状态开麦。
- 恢复后的音频 **MUST NOT** 补造/拼接缺口。

**AC-029**

- Given 可恢复中断，When 自动恢复成功，Then 新分片生成，gap 可见。
- Given App 被杀后重启，When 前台，Then 3 秒倒计时可取消；后台不静默开麦。
- Given 静默恢复开启，When 恢复，Then 无应用提示音/触觉，但系统指示可见。

### FR-030 录音完整性保护（P0）

- 物理分片 **MUST** 60 秒或 2 MB 封口，原子写入、校验和、manifest。
- 录音链路 **MUST NOT** 静默改变采样率/码率/声道/分片参数；低功耗档位必须由用户显式选择并递增 `formatVersion`。
- 启动 **MUST** 扫描 `.part`/孤立/缺失/校验失败；能修则修，不能修标记 `.corrupt` 并保留。
- 缺失序号 **MUST** 先查 manifest 的 `reclaimed/deleted/audioPurged` 与墓碑；正常清理不得报 missing，只有未标记的意外缺失才报。
- 损坏分片 **MUST NOT** 进入转写/传输，**MUST NOT** 静默删除；UI 可见。
- 传输两端 **MUST** 校验；不一致重传，永久不一致标记损坏。
- 断电/被杀 **MUST** 保证已封口分片完整；损失 ≤ 60 秒。

**AC-030**

- Given 强制退出/断电，When 重启，Then 已封口分片完整，损失 ≤ 60 秒。
- Given 注入损坏分片，When 扫描，Then 隔离 `.corrupt`，不转写，UI 可见。

### FR-031 实时诊断日志（P0）

- 应用 **MUST** 提供实时诊断日志视图，覆盖 recording/transfer/transcription/storage/location/battery/ui/diagnostics。
- 日志 **MUST** 实时更新，支持级别/分类过滤、暂停、清空、导出。
- 日志 **MUST NOT** 含音频、转写、经纬度、地址、文件名；ID 截断；错误用错误码。
- Release 默认 info；debug 需用户显式开启；文件 7 天/5MB；导出前提示；不上传。
- 日志写入 **MUST NOT** 阻塞音频回调/主线程。

**AC-031**

- Given 录音中，When 打开诊断页，Then 实时看到录音/传输事件，无敏感内容。
- Given 导出，When 生成文件，Then 可读且无敏感内容，导出前有提示。

### G-001 连续 24 小时可行性门禁（P0）

- **MUST** 按 `../specs/24h-feasibility.md` 在真机执行完整 24 小时测试。
- 通过标准：音频连续 24h、分片 0 丢失/0 损坏、设备未因电量/热关机、24h 结束电量 ≥ 5%、热状态未进入 `critical`。
- 测试矩阵至少覆盖：主设备 2 次、上一代 1 次、最旧支持型号 1 次；**立体声 96 kbps/声道基线**；64 kbps/声道仅作降级评估（需用户确认）；iPhone 在旁/不在旁。
- 未通过时：
  - 不得对外承诺 24h；
  - 记录实际最大连续时长与失败原因；
  - 按 `../decisions/0004-24h-recording-requirement.md` 评估降级方案，由用户确认。
- 门禁结果 **MUST** 回写 `../specs/24h-feasibility.md` 与 `../specs/recording.md`。

### G-002 24h 录音 + GPS 可行性门禁（P0）

- **MUST** 按 `../specs/gps-tracking.md` 在真机执行。
- 通过标准：G-001 仍通过；每 5 分钟至少 1 点；移动中缺口 ≤6 分钟；户外移动窗口覆盖 ≥90%；水平精度中位数 ≤ 30m、90 分位 ≤ 100m；GPX 按会话起止裁剪且可解析；24h 结束电量 ≥ 5% 且设备未关机。
- 未通过时不得对外承诺 24h + GPS；按 `../decisions/0005-gps-tracking.md` 评估降频、GPS 可选化或调整目标。
- 结果 **MUST** 回写 `../specs/gps-tracking.md` 与 `../specs/24h-feasibility.md`。

### G-003 5% 低电量告警门禁（P0）

- **MUST** 按 `../specs/battery-alerting.md` 真机执行。
- 通过标准：5% 通知 60s 内送达；去重；TTL 过期才丢弃，乱序告警仍按 eventID + 最新状态处理；前台/点击启动 Live Activity；更新/结束；8 小时上限正常；录音不受影响；通知/Live Activity/日志无敏感内容。
- 未通过时不得宣称“自动灵动岛/警报级”；按 `../decisions/0006-low-battery-alerting.md` 降级。
- 结果 **MUST** 回写 `../specs/battery-alerting.md` 与 ADR-0006。

### G-004 录音保活/完整性门禁（P0）

- **MUST** 按 `../specs/recording-health.md` 真机执行。
- 通过标准：强制退出/断电已封口分片 0 损坏；损失 ≤ 60 秒；中断 30 秒内标记、60 秒内通知；自动恢复 3 次内成功；损坏隔离；24h 无误报。
- 未通过时不得宣称“绝不丢失/绝不损坏”；按 ADR-0007 调整。
- 结果 **MUST** 回写 `../specs/recording-health.md` 与 ADR-0007。

### G-005 诊断日志门禁（P0）

- **MUST** 按 `../specs/diagnostics.md` 执行。
- 通过标准：日志/导出无敏感内容；配额/清空有效；导出前提示；Release 默认 info；1000 条渲染 P95 < 100ms；Watch 转发不显著耗电。
- 未通过时按 ADR-0008 降级，不得关闭脱敏。
- 结果 **MUST** 回写 `../specs/diagnostics.md` 与 ADR-0008。

| NFR-018 | 中断通知 | 中断后 30 秒内状态可见，60 秒内通知（iPhone 可达） | 真机 |
| NFR-019 | 诊断日志 | 实时、脱敏、7 天/5MB、P95 < 100ms | 审查 + 性能 |
| NFR-020 | 备份 | 设备级 iCloud 备份包含录音/元数据；App 不上传；用户可管理空间 | 备份恢复测试 |
